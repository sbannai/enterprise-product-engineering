# Requirement Implementation Packages

Each REQ package is generated from the controlled BRD/SRS mapping and XX01–XX06 implementation family. Runtime behavior, persistence adapters, external contracts and acceptance execution must be bound to approved contracts before promotion.


## Versioned product feature requirements

The controlled additive product requirements register is maintained in [EPER Product Requirements — Versioned Feature Additions](../docs/requirements/EPER_PRODUCT_REQUIREMENTS_CHANGE_CONTROL_v1.7.0_DRAFT.md). The cumulative v1.7.0 document retains earlier candidate history; the customer asset repository is additive candidate EPER-CW-060 and remains draft pending owner approval.

**Mandatory change rule:** every new feature addition receives a unique requirement ID, a MINOR document-version increment, testable acceptance criteria, and traceability across UX/UI, API, data, events/audit, security, tests, release and user documentation. The existing 228 requirements across 38 chapters remain unchanged unless a separately approved baseline change explicitly authorizes otherwise.
